# E-Commerce Platform — Project Specification

A self-hosted online store built with **Django**. No Shopify, no monthly platform fees — you own the code, the data, and the design. Responsive, fast, easy for customers to shop, and easy for admins to manage products.

---

## 1. Goals

- A custom, fully responsive storefront (mobile-first).
- A clean, simple admin experience so non-technical staff can add/edit products without touching code.
- Full control over design, features, and data.
- Secure checkout and payment handling.
- Room to grow (SEO, multiple payment methods, discounts, etc.).

---

## 2. Tech Stack

| Layer | Choice | Why |
|-------|--------|-----|
| Backend | **Django 5.x** (Python 3.12+) | Batteries-included, great admin, secure by default |
| Database | **PostgreSQL** | Robust, production-ready (SQLite fine for local dev) |
| Frontend | **Django Templates + HTMX + Alpine.js** *(or React/Next.js if you want an SPA)* | HTMX keeps it simple and server-rendered; React if you need a richer app |
| Styling | **Tailwind CSS** | Fast, responsive, consistent design system |
| Media/Images | Local in dev, **AWS S3 / Cloudflare R2** in production | Scalable image hosting |
| Payments | **Stripe** (primary), optional PayPal | Well-documented, handles cards securely |
| Auth | Django auth + optional social login (`django-allauth`) | Built-in, extensible |
| Background tasks | **Celery + Redis** | Emails, order processing, etc. |
| Search | Postgres full-text (start) → Elasticsearch/Meilisearch (later) | Product search |
| Deployment | **Docker** + Gunicorn + Nginx; host on Railway / Render / VPS / Fly.io | Reproducible, portable |

## 3. Core Features

### Storefront (Customer-Facing)
- Home page with featured/new products.
- Product listing with filters (category, price, attributes) and sorting.
- Product detail page: image gallery, description, variants (size/color), stock status, related products.
- Search bar.
- Shopping cart (add/remove/update quantity), persists for logged-in users.
- Guest checkout + registered checkout.
- Checkout flow: shipping info → payment → confirmation.
- Order confirmation page + email receipt.
- User accounts: order history, saved addresses, profile.
- Wishlist *(optional)*.
- Fully responsive across mobile, tablet, desktop.

### Admin (Staff-Facing)
- Easy product management via the **Django Admin** (customized) — add/edit/delete products, upload images, set prices, manage stock.
- Bulk actions (publish/unpublish, adjust stock).
- Category and variant management.
- Inventory tracking with low-stock alerts.
- Order management: view, update status (pending → paid → shipped → delivered), refunds.
- Customer list.
- Discount/coupon codes.
- Dashboard with basic sales stats.

> The Django admin gives you a powerful product-management UI out of the box. Customizing it (list views, image previews, inline variant editing) is far faster than building an admin panel from scratch.

## 4. Data Models (Overview)

```
Category
  - name, slug, parent (self-FK for subcategories), image

Product
  - name, slug, description, category (FK)
  - base_price, is_active, created_at, updated_at
  - SEO fields (meta_title, meta_description)

ProductImage
  - product (FK), image, alt_text, is_primary, order

ProductVariant         # e.g. Size M / Color Red
  - product (FK), name, sku, price_override, stock_quantity

Cart
  - user (nullable for guests), session_key, created_at

CartItem
  - cart (FK), variant/product (FK), quantity

Order
  - user (nullable), email, status, total, created_at
  - shipping_address, billing_address
  - payment_intent_id (Stripe)

OrderItem
  - order (FK), product/variant (FK), quantity, price_at_purchase

Address
  - user (FK), line1, line2, city, state, postal_code, country, phone

Coupon
  - code, discount_type (% or fixed), value, valid_from, valid_to, active
```

## 6. Responsive Design Principles

- **Mobile-first**: design for small screens, scale up.
- Tailwind breakpoints: `sm` `md` `lg` `xl`.
- Touch-friendly buttons and tap targets (min 44px).
- Lazy-load images; serve responsive image sizes.
- Fast load times: minify assets, cache, use a CDN.
- Accessible: semantic HTML, alt text, keyboard navigation, sufficient contrast.

---

## 7. Security Checklist

- Store secrets in environment variables (use `django-environ`).
- `DEBUG = False` in production.
- HTTPS only; set `SECURE_SSL_REDIRECT`, HSTS, secure cookies.
- CSRF protection (Django default — keep enabled).
- Never store raw card data — let Stripe handle it.
- Validate and sanitize all user input.
- Rate-limit login and checkout endpoints.
- Keep dependencies updated.

## 8. Build Phases (Roadmap)

**Phase 1 — Foundation**
- Set up Django project, settings split, PostgreSQL, Tailwind.
- Build catalog models + customized admin.
- Product listing & detail pages.

**Phase 2 — Shopping**
- Cart (session + user-based).
- Checkout flow.
- Stripe payment integration.
- Order creation + confirmation emails.

**Phase 3 — Accounts & Admin Polish**
- User registration/login, order history, addresses.
- Order management dashboard for staff.
- Coupons/discounts.

**Phase 4 — Launch Prep**
- SEO (sitemaps, meta tags, clean URLs).
- Image hosting on S3/R2.
- Dockerize, deploy, set up domain + SSL.
- Analytics, error monitoring (Sentry).

**Phase 5 — Growth (later)**
- Better search, reviews/ratings, wishlists, multi-currency, marketing emails.

## 10. Notes & Recommendations

- **Start with HTMX + Django templates**, not React, unless you specifically need an app-like SPA. It's dramatically simpler and the storefront will still feel modern and fast.
- **Lean on the Django admin** for product management — it's the single biggest reason this stack fits your "easy for admins" requirement.
- Don't build payments yourself. Use Stripe Checkout or Payment Elements.
- Set up version control (Git) and a staging environment before launch.
- Write tests for cart logic and checkout — that's where bugs hurt most.
